# 2026roboB：足回り・発射機構プロジェクト

元の C:\mbedOffline44\Programs\2026roboB と 2026roboB_sub から新規作成したプロジェクトです。元フォルダとKiCadファイルは変更していません。

- `2026roboB_hwenc`：4輪メカナム、MU3受信、発射側へのUART送信。
- `2026roboB_sub_hwenc`：UART受信、TIM8/TIM1のハードウェアエンコーダ、アーム・ドラム制御、計測CSV。

## 開発環境とビルド

mbed OS 2、NUCLEO-F446RE、既存の C:\mbedOffline44 にあるGCC ARMを使います。mbedライブラリは複製せず、C:\mbedOffline44\Datas\MbedOS2 を参照します。

各フォルダで `build.bat` を実行してください。または `startCmd.bat` を起動し、対象フォルダへ移動して `compile NUCLEO_F446RE` を実行します。

生成される書き込みファイル：

```
2026roboB_hwenc/BUILD/NUCLEO_F446RE/GCC_ARM/2026roboB_hwenc.bin
2026roboB_sub_hwenc/BUILD/NUCLEO_F446RE/GCC_ARM/2026roboB_sub_hwenc.bin
```

フォルダはそのまま C:\mbedOffline44\Programs 配下へコピーして使えます。各 `.mbed` にSDK・コンパイラの参照先を設定済みです。

## 前提とする基板変更：両基板共通

| 信号 | 現在のPCB | 変更後 | 使用するタイマ |
|---|---|---|---|
| J1 A相、R15 MCU側 | PC4 | PC6 | TIM8_CH1、AF3 |
| J1 B相、R16 MCU側 | PA12 | PC7 | TIM8_CH2、AF3 |
| J2 A相 | PA8 | PA8 | TIM1_CH1、AF1 |
| J2 B相 | PA9 | PA9 | TIM1_CH2、AF1 |
| MD3_PWM2 | PA10 | PA6 | TIM13_CH1、`PA_6_ALT0` |
| MD5_PWM1 | PA11 | PA7 | TIM14_CH1、`PA_7_ALT2` |

古いMCU側接続を外して変更先へ配線します。元のGPIOと変更先を同時接続する形にはしません。J1/J2の5V・GNDおよび直列抵抗は維持します。

元プログラムのJ1宣言はPC5・PC4でしたが、現在のPCBはPC4・PA12です。本プロジェクトでは変更後のPC6・PC7を明示的に使用します。

## モータ・通信の割り当て

| 用途 | PWM1 / PWM2 | タイマ | 反転 |
|---|---|---|---|
| 足回り・左前 MD1 | PB4 / PC8 | TIM3_CH1 / TIM3_CH3 | false |
| 足回り・右前 MD2 | PC9 / PB8 | TIM3_CH4 / TIM2_CH1 | true |
| 足回り・左後 MD3 | PB3 / PA6_ALT0 | TIM2_CH2 / TIM13_CH1 | false |
| 足回り・右後 MD4 | PB10 / PB5 | TIM2_CH3 / TIM3_CH2 | true |
| 発射側・アーム MD1 | PB4 / PC8 | TIM3_CH1 / TIM3_CH3 | false |
| 発射側・ドラム MD2 | PC9 / PB8 | TIM3_CH4 / TIM2_CH1 | false |
| MD5（今回は未使用） | PA7_ALT2 / PB2 | TIM14_CH1 / TIM2_CH4 | — |

MD5はこのプロジェクトでインスタンス化しません。表の割り当ては、使用中SDKのコンパイル済みピン表で確認しています。PB8は通常名ではTIM2_CH1で、`PB_8_ALT0`ならTIM4_CH3ですが、本プロジェクトでは元のPB8指定を維持します。

タイマは各ボード内の資源です。足回り側と発射側でTIM3などを同じ名前で使用しても競合しません。TIM1/TIM8は発射側のエンコーダ専用です。PC8/PC9は`_ALT0`を付けず、TIM3を選択します。同じタイマのPWMは周波数を共有するため、既存KKMDの全モータ2kHzを維持します。

| 通信 | 接続 | 設定 |
|---|---|---|
| MU3→足回り | MU3 TX → 足回りPC11、MU3 RX ← 足回りPC10 | 19200 baud、8N1 |
| 足回り→発射 | 足回りPB6 TX → 発射PA1 RX | 115200 baud、8N1 |
| 戻り線 | 発射PA0 TX → 足回りPB7 RX | 今回は返信なし |
| 基板間 | GNDを共通にする | — |
| PCログ | ST-LINK仮想COM、USBTX/USBRX | 115200 baud、8N1 |

MU3のチャンネル15、グループ110、自局2、相手1は元コードを維持しています。

発射側のMU3ソースは元のまま保存していますが、`.mbedignore`でビルド対象から外しています。元コードではこのソースと基板間UARTが両方PA0/PA1を初期化していました。発射側のPCログ用Serialはmain.cppに置きます。

## 調整方法

発射側 `control_config.hpp` を変更します。

| 設定 | 初期値 | 意味 |
|---|---|---|
| ARM_PPR / DRUM_PPR | 2048 | エンコーダ本体の1回転あたり周期数。4逓倍前の値 |
| ARM_ENCODER_SIGN / DRUM_ENCODER_SIGN | -1 / +1 | カウントの正方向。実機で確認 |
| ARM_LOAD_DEG | 90° | 起動・発射開始時のアーム位置からの巻上げ角度 |
| DRUM_STEP_DEG | 72° | 1装填分の角度 |
| ARM_RELEASE_DROP_DEG | 17.578125° | 再始動時の角度から、この角度以上戻ったらモータ停止 |
| POSITION_TOLERANCE_DEG | 2° | 停止位置の許容差 |
| STOP_SPEED_DEG_S | 5°/s | 停止とみなす角速度 |
| SLOW_ZONE_DEG | 6° | 目標直前の減速区間 |
| SETTLE_US | 100000 µs | 低速状態を100ms継続して停止確認 |

2048 PPRは元コードの定数から採用した仮の初期値です。エンコーダ本体のスイッチ設定と一致させてください。1回転で8192カウントなら、この値で正しく360°になります。

旧コードのアーム380カウントは、2048 PPR・2逓倍なら約33.4°です。今回の90°設定はユーザー指定に基づく変更であり、旧停止位置を再現する設定ではありません。必要ならARM_LOAD_DEGを実機の停止位置に合わせて変更してください。

この制御は目標直前で減速し、目標に到達したら既存KKMDの停止操作を行います。PIDによる保持や、停止後に逆回転して誤差を修正する制御ではありません。停止誤差が許容値を超えた場合はFAULTにします。

## 発射シーケンス

1. 起動時はアームの所定の待機位置と、ドラムの初期装填位置に合わせてください。原点センサは未実装です。
2. 足回り側が有効なMU3データを受信し、ボタン値`n`を受信すると発射を受け付けます。
3. `i`への変化で1回だけ開始します。アーム位置を相対0°にして巻き上げます。
4. アーム90°付近でモータを止め、角速度と停止位置を確認します。
5. ドラムを72°ずつ進め、停止確認後にアームモータを再始動します。
6. アーム角度が解放検出量だけ戻ったらモータを止めます。アームが静止してから待機へ戻ります。
7. 次の発射には、待機中に`n`を受信してから再び`i`を受信する必要があります。

ドラムの目標角度は72°→144°→216°と累積します。装填ごとにエンコーダを0に戻さないため、停止誤差を次の目標位置へ足し込みません。アームは各発射開始時の実位置を0°とします。毎回の物理原点の保証は原点センサや機構側の位置決めが必要です。

MU3更新が500ms途切れると足回りを停止し、発射側へ`!`を送ります。基板間UARTが500ms途切れた場合も発射モータを停止します。動作中の通信断・動作タイムアウト・停止位置異常はFAULTとして保持し、確認後にボードをリセットして復帰します。ばね解放後の機械運動をモータ停止だけで止めることはできません。

旧KKMDのPWM操作と2kHz設定は変更していません。「停止」は既存KKMDで0を設定する操作で、ドライバの実際の停止挙動は既存回路に従います。

## 角度・角速度のCSV

発射側の仮想COMを115200 baudで開きます。待機中またはFAULT時に小文字`p`を送ると現在の角度・角速度・カウントを表示し、PPRや方向の確認に使えます。発射中は約1msごとにカウンタを読み、約10msごとと状態遷移時に角度・角速度をRAMへ記録します。待機中またはFAULT時に小文字`d`を送ると、直近の発射のCSVを出力します。

```
time_ms,state,arm_deg,arm_deg_s,drum_deg,drum_deg_s,arm_raw_deg_s,drum_raw_deg_s
```

- `arm_deg_s` / `drum_deg_s`：約20msの一次ローパスを通した角速度。停止判定にも使用。
- `*_raw_deg_s`：直近のカウント差分から求めた角速度。微分の量子化ノイズを含みます。
- state：0待機、1巻上げ、2アーム停止確認、3ドラム回転、4ドラム停止確認、5解放操作、6発射後停止確認、7FAULT。
- 最大2048件のリングバッファです。長い動作では古いサンプルから上書きし、最新約20秒分を保持します。次の発射開始時に記録を更新します。
- CSVの角速度は10msごとに保存する瞬時値です。10msより短いピークの最大値を保証する計測ではありません。
- 状態メッセージとCSVは同じCOMへ出ます。表計算へ取り込む際はCSVヘッダからデータ行を使用してください。
- 記録にはアームとドラムの角度が入りますが、雑巾の離脱そのものは検出しません。発射角度や飛距離との対応は実測で確認します。

## 変更範囲と検証

各元プロジェクトの `2026roboconlib` はファイル内容を維持しています。MU3、KKMD、aRohmMD、aTB6643KQ、useful、旧エンコーダライブラリをコピーしてあります。新しいhardware_encoderを使用するため、旧エンコーダのグローバルインスタンスは作りません。足回りのLimitswitchクラスも保存していますが、未使用のPA13入力は生成せず、SWDとの重複を避けています。

足回りのメカナム計算・正規化・モータ反転は維持しています。通信更新の一括読み取り、20ms周期のUART送信、通信断停止を追加しました。発射側は角度・角速度で判定する状態制御に変更しました。

既存SDKで両プロジェクトのビルドとリンクを確認し、binを生成しています。PC上で実装ヘッダを使い、フレーム解析、予約バイトの復元、不正フレーム、カウンタ折り返し、2回の発射、押しっぱなし防止、通信断、動作タイムアウト、停止位置異常、時刻の折り返しを検証しました。実機の回転方向・PPR・停止位置・PWM極性・発射動作は未検証です。

最初に無負荷で両エンコーダの正負と1回転換算を確認し、停止角度・角速度・PWMを調整してください。解放検出量と状態タイムアウトも機構の動作時間に合わせて調整できます。
